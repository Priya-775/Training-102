# What I Learned

## 1. QA (Quality Assurance)

I learned that Quality Assurance (QA) is the process of ensuring that software works correctly before it reaches users. In AI applications, QA is even more important because the responses generated by AI can vary depending on the input.

QA involves:
- Testing application functionality
- Finding bugs and errors
- Validating AI responses
- Improving reliability
- Ensuring a better user experience

In AI products, QA is not only about testing code but also about evaluating whether the AI produces accurate, relevant, and safe responses.

## 3. Software Architecture

Software Architecture refers to the overall design and structure of a software system.

I learned that before writing code, developers first decide:

- How different components will interact.
- How data will flow.
- Which technologies will be used.
- How the application can scale in the future.

A well-designed architecture makes applications:
- Easier to maintain
- More secure
- Faster
- Scalable
- Easier to update

For AI applications, architecture often includes:

User → Frontend → Backend → AI Model → Database → Response

## 5. LLMs + Transformers

We revisited Large Language Models (LLMs) and Transformer architecture in greater detail.

I learned that:

Transformers are the deep learning architecture that powers modern language models.

LLMs are built using transformer architecture and trained on massive amounts of text.

The Transformer uses a mechanism called **Self-Attention**, allowing the model to understand relationships between words regardless of their position in a sentence.

Examples include:
- ChatGPT
- Gemini
- Claude
- Llama

These models can:
- Generate text
- Answer questions
- Translate languages
- Summarize documents
- Write code

## 6. Function Calling / Tool Calling in Generative AI

One of today's most interesting topics was Function Calling (also known as Tool Calling).

Normally, an AI model only generates text.

However, using function calling, an AI can interact with external tools and services.

For example, an AI assistant can:

- Check today's weather
- Book appointments
- Search databases
- Call APIs
- Perform calculations
- Access business information

Instead of simply responding with text, the AI decides when to use an external function to complete a task.

This significantly increases the practical capabilities of Generative AI systems.

## 7. Biggest Problem in Enterprise AI – Orchestration

An important discussion today focused on one of the biggest challenges in enterprise AI:

**Orchestration**

Modern AI systems consist of multiple components:

- LLMs
- APIs
- Databases
- Memory
- Multiple AI agents

Managing all these components efficiently is known as orchestration.

Without proper orchestration:
- Tasks become disorganized.
- AI workflows fail.
- Data is lost.

## 8. Episodic Memory

Today's session introduced Episodic Memory in AI.

Episodic Memory allows an AI system to remember previous interactions or events.

For example:

User:
> My favorite programming language is Python.

Later...

User:
> Recommend a project.

AI:
> Since you like Python, here are some Python-based AI projects.

This makes conversations more personalized and natural.

## 9. RAG (Retrieval-Augmented Generation) – Large Scale Memory

We explored RAG in greater detail.

Traditional LLMs only use the knowledge learned during training.

RAG improves this by retrieving information from external sources before generating a response.

These external sources may include:
- PDFs
- Company documents
- Research papers
- Databases
- Websites
- Knowledge bases

Because of this, RAG acts like a large external memory system.

Advantages include:
- More accurate responses
- Updated information
- Domain-specific knowledge
- Reduced hallucinations

---

## 10. RAG Pipeline

Finally, I learned how a RAG Pipeline works.

The overall workflow is:

1. User submits a query.
2. The query is converted into vector embeddings.
3. The Vector Database searches for similar information.
4. Relevant documents are retrieved.
5. The retrieved context is sent to the LLM.
6. The LLM generates the final response.
7. The user receives an accurate answer.

This pipeline combines retrieval and generation to improve response quality.
